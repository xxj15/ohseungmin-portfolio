- **누구의 사이트인가**: 오승민(서강대학교 유럽문화학과 독일어권 심화 · 경영학 복수전공, Sogang Wise Investment Club 38기).

- **위치**: 이력서를 대체하지 않는다. 이력서로는 다 보여줄 수 없는 **분석 과정(문제 → 가설 → 검증 → 결론)**을 깊게 보여주는 보완 자료다.

## 2. 목표 · 비목표 · 반목표

**목표**
- 첫 화면에서 "산업 구조를 분석하고 기업가치로 결론 내는 사람"이라는 정체성이 바로 읽힌다.
- 케이스마다 결론과 숫자가 먼저 보이고(BCG Client Impact 방식), 상세에서는 배경 → 질문 → 가설 → 방법 → 결과 순서로 근거를 확인할 수 있다(Kim Duff Selected Work 방식).
- 본인이 쓴 SWIC 리포트 PDF를 사이트에서 바로 열람할 수 있다.

**비목표**
- 블로그, 다국어(영문) 버전, CMS, 문의 폼, 다크 모드, 방문자 분석 도구.

**반목표 (기술적으로 돌아가도 이러면 실패)**
- **AI가 쓴 것 같은 문구.** 사용자가 두 번 지적했다. 아래 §6 문구 규칙을 반드시 지킨다.
- **비공개 자료 노출.** SG Fenero IM 장표 원본·세부 수치, 공개 여부가 확인되지 않은 장표의 게시.
- **성과 과장.** 독립 리서치(학회·스터디)와 실제 실무 기여(인턴·IM)를 섞어 부풀리지 않는다. 고객사 성과를 자기 성과처럼 쓰지 않는다.
- **색 띠 배경.** 배경은 전부 흰색이어야 한다(사용자 결정). 네이비·회색으로 칠한 섹션 띠, 회색 카드 면 금지.
- **수치 창작.** 인벤토리·리포트 원문에 없는 숫자를 만들지 않는다.

확정 시안은 `docs/superpowers/mockups/`에 있다. **시각 기준은 이 파일들**이다(1440px 데스크톱 기준으로만 디자인됨).

- `home-v8.html` — 홈
- `detail-hanwha.html`, `detail-hd.html`, `detail-rci.html`, `detail-msp.html`, `detail-im.html`, `detail-bok.html`, `detail-macro.html` — 케이스 상세 7개

- 흰 배경 규칙은 각 시안 `<style>` 끝의 `white-only override` 블록에 반영되어 있다. 구현 시 이 덮어쓰기 결과가 최종 모습이다(덮어쓰기 구조 자체를 옮기지 말고 최종 값으로 정리).

## 6. 문구 규칙 (반목표 1 방지)

사용자가 "AI스럽다"고 지적한 표현을 기준으로 정했다.

- 섹션 제목은 **영문 라벨 + 한글 명사** ("SELECTED WORK / 주요 프로젝트"). "이런 일을 해 봤습니다", "편하게 연락 주세요" 같은 **말 거는 문장 금지**.
- 케이스 제목은 **명사형** ("~에 따른 실적 추정과 기업가치 평가"). 질문형 제목 금지. 단, 상세 페이지의 "핵심 질문" 블록 한 문장은 예외.
- 설명은 **사실 서술 또는 개조식**. "~을 번역하다", "~에 닿기까지", "맥락을 읽고 숫자로 검증해" 같은 수사, 대시(—)로 꾸미는 문장, 세 개씩 짝 맞춘 나열 금지.
- 리포트는 본인이 붙인 원제("Cellf-made Orange", "애국합시다", "걱정은 Kevin Warsh가 Wash~")를 그대로 쓴다.
- 새 문구가 필요하면 위 규칙으로 쓰고, 최종 확인은 사용자(서진)·본인(승민)에게 받는다.

## 8. 기술 구성

- **스택**: Astro(정적 출력) + TypeScript. 서진 저장소와 같은 주요 버전대(Astro 7.x, Node ≥ 22)로 맞춘다. 추가 UI 라이브러리 없음. 차트는 시안처럼 HTML/CSS·인라인 SVG로 그린다(차트 라이브러리 불필요).
- **데이터 모델**: 서진 사이트처럼 `src/data/`에 TypeScript 데이터 파일. 케이스 하나 = 하나의 객체(메타·사실표·숫자 띠·블록 배열·이전/다음 순서). 블록은 종류별 타입(목록, 질문, 가설, 카드 그리드, Exhibit-막대/선/표/흐름도/계산 막대, 리포트 비교, 안내문)으로 나누고 상세 페이지는 블록 배열을 순서대로 렌더링한다.
- **라우팅**: `/` 홈, `/work/[slug]/` 케이스 상세 7개(정적 생성), 404.
- **배포**: 서진 저장소의 `.github/workflows/deploy.yml` 구조를 그대로(main push → build → Pages). `ASTRO_BASE`로 하위 경로 대응, 모든 내부 링크는 `withBase()`를 거친다(서진 `src/lib/paths.ts` 방식).
- **메타**: 페이지별 `<title>`, `og:title`. OG 이미지는 이번 범위에서 선택 사항.
- **테스트**: Playwright 스모크 테스트 — 홈 렌더링, 7개 상세 페이지 200 응답과 h1 존재, 홈 카드 → 상세 링크, 이전/다음 링크 순환, 리포트 PDF 링크 존재, 흰 배경 확인(섹션 배경색이 흰색인지).
